# Zapret2 WebControl

Локальная веб-панель управления `zapret2` с общим API и платформенными бэкендами.

На первом этапе проект ориентирован на Windows и предоставляет полный локальный
контур управления `winws2`: редактируемые стратегии и списки, предпросмотр и
проверку команды, управляемый процесс, журнал, Blockcheck2 и автозапуск через
отдельную службу Windows. Любое системное действие требует явного подтверждения
в API/UI. Перед запуском панель требует устранить предупреждения предпросмотра и
проверяет команду через `winws2 --dry-run`.

## Быстрый старт

```powershell
py -m venv .venv
.\scripts\bootstrap_windows.ps1
.\run.ps1
```

Откройте <http://127.0.0.1:8787>.

Если `winws2.exe` не находится через `PATH`, задайте каталог установки:

```powershell
$env:ZAPRET2_DIR = 'C:\Tools\zapret2'
py -m zapret2_webcontrol
```

Bootstrap закрепляет официальный `zapret-win-bundle` на проверенном commit,
скачивает четыре отсутствующих в нём payload из закреплённых revisions Flowseal
и zapret-openwrt и проверяет их SHA-256. Каталоги `vendor/` и `runtime/`
исключены из основного Git-репозитория. Если бандл уже установлен отдельно,
можно выполнить `bootstrap_windows.ps1 -SkipBundle` и задать `ZAPRET2_DIR`.

## Что уже есть

- `/api/v1/health` — проверка доступности панели;
- `/api/v1/system` — сведения о платформе и возможностях бэкенда;
- `/api/v1/status` — read-only статус `winws2`;
- `/api/v1/strategies` — общий каталог профилей;
- `/api/v1/strategies/preview` — скомпилированная команда `winws2` без запуска;
- `PATCH /api/v1/strategies/{id}` — безопасное изменение профиля;
- `POST /api/v1/strategies` — создание пользовательского профиля;
- `DELETE /api/v1/strategies/{id}` — подтверждённое удаление только
  пользовательского профиля;
- `POST /api/v1/strategies/reset` — подтверждённый сброс пользовательских изменений;
- `/api/v1/lists` и `/api/v1/lists/{id}` — просмотр и атомарное редактирование
  доменных списков;
- `/api/v1/logs/runtime` — журнал управляемого `winws2`;
- `/api/v1/blockcheck/status|log|start|stop` — управление официальным
  Windows Blockcheck2;
- `/api/v1/autostart` и `/install|remove` — состояние и управление отдельной
  службой `zapret2-webcontrol`;
- `POST /api/v1/runtime/start` и `/stop` — управляемый процесс с JSON-подтверждением;
- платформенная фабрика без импорта Windows API на Linux;
- безопасный Linux-бэкенд для каталога, списков и предпросмотра `nfqws2`;
- импорт Linux/OpenWrt UCI-блоков через `reference_importer.parse_uci_strategies`;
- локальная web-панель с включением, выключением, созданием, копированием,
  редактированием и удалением пользовательских профилей;
- атомарное хранение только пользовательских overrides в
  `runtime/config/strategies.json`, без изменения эталонного каталога;
- стандартная библиотека Python, без внешних зависимостей.

Каталог сейчас содержит все 34 стратегии из эталонной LuCI-конфигурации:
8 включённых и 26 сохранённых выключенных вариантов. Все 34 профиля проходят
реальную проверку локальным `winws2 --dry-run`; полная активная конфигурация
также проходит проверку без предупреждений.
Для Discord media/STUN Windows-бэкенд использует штатные
`windivert_part.discord_media.txt` и `windivert_part.stun.txt` из
официального Windows-бандла.

Изменения стратегий сохраняются разреженными overrides, а списки — отдельными
файлами в `runtime/`. Установка службы всегда компилирует текущую конфигурацию;
панель помечает службу как устаревшую и не запускает её, если стратегии после
этого были изменены. Чужие процессы `winws2` панель обнаруживает, но не завершает.
Пользовательские стратегии хранятся рядом с overrides, но отдельно от 34
эталонных профилей. Эталонный профиль нельзя удалить: его можно выключить,
изменить или скопировать в собственный вариант.

Blockcheck2 временно меняет сетевое поведение Windows и запускается только после
отдельного подтверждения. Панель не запускает его автоматически и не разрешает
одновременную работу с основным `winws2`.

На Linux панель уже открывается с тем же фронтендом, находит `nfqws2` в
`ZAPRET2_DIR` или `/opt/zapret2`, сохраняет общий каталог и формирует команду с
`--qnum=300`. Запуск пока намеренно заблокирован: для него нужен атомарный слой
NFQUEUE + nftables/iptables и гарантированный rollback, иначе один `nfqws2`
создаёт ложное впечатление рабочей конфигурации.

## Принципы первого этапа

- слушаем только `127.0.0.1`;
- не запускаем и не останавливаем `winws2` автоматически;
- Linux firewall/nft/u32-части не смешиваем со стратегиями: они останутся в Linux-бэкенде;
- при конвертации и редактировании сохраняем порядок `--in-range`, `--out-range`, `--payload`,
  `--lua-desync` и hostlist-исключения, а
  неподдержанные Linux blob-ресурсы показываем предупреждением;
- не храним токены, логи, локальные настройки и binary payload в Git;
- локально импортированные списки и blob-файлы лежат в `runtime/lists` и
  `runtime/blobs`; каталог `runtime` исключён из Git;
- платформенные операции изолированы в `backend/`.

Реальные параметры OpenWrt/LuCI и отличия, влияющие на Windows-порт, собраны в
[наблюдениях по роутеру](docs/ROUTER_REFERENCE.md).

## Импорт Linux/OpenWrt-конфига

Парсер принимает исходный файл с блоками `config strategy` и преобразует его в
общий формат профилей. Например:

```python
from pathlib import Path
from zapret2_webcontrol.reference_importer import load_uci_strategies

strategies = load_uci_strategies(Path("zapret2"))
```

Поля `option script` с `--payload`, `--lua-desync`, `--in-range` и
`--out-range` переносятся в профиль. Очереди NFQUEUE, nftables/u32 и shell-
обвязка намеренно не переносятся: это Linux-слой, для Windows используется
WinDivert capture-команда.
