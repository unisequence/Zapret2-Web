# Установка на Windows

Самый простой способ — скачать ZIP последнего релиза, распаковать его и запустить `setup.bat`. Git устанавливать не нужно. Скрипт проверит требования, при необходимости установит Python, подготовит окружение и Windows-ресурсы, затем запустит панель.

## Требования

| Компонент | Требование |
| --- | --- |
| Windows | Компьютер, на котором должен работать `winws2` |
| Python | 3.11 или новее; если его нет, `setup.bat` установит Python 3.13 через WinGet |
| Git | Не требуется для установки из релизного ZIP. Нужен только для разработки через `git clone` или для проверки ранее установленного Git-бандла |
| WinGet | Нужен только для автоматической установки Python; входит в App Installer в актуальных версиях Windows |
| Интернет | Нужен для клонирования и загрузки закреплённого бандла и проверенных ресурсов |

Официальная страница: [Python для Windows](https://www.python.org/downloads/windows/).

## 1. Получить проект

Откройте [страницу релизов](https://github.com/unisequence/Zapret2-Web/releases) и скачайте **Source code (zip)** у нужной версии. Затем распакуйте архив, например, в `Загрузки\Zapret2-Web`.

Для разработки вместо ZIP можно клонировать репозиторий:

```powershell
git clone https://github.com/unisequence/Zapret2-Web.git
cd Zapret2-Web
```

Если проект уже распакован или клонирован, перейдите в его папку и продолжайте со следующего шага.

## 2. Запустить установку

```powershell
.\setup.bat
```

`setup.bat` выполняет следующие шаги:

1. Проверяет наличие Python 3.11+.
2. Если подходящего Python нет, устанавливает Python 3.13 для текущего пользователя командой WinGet `Python.Python.3.13`. WinGet может запросить подтверждение условий. Условия автоматически не принимаются.
3. Создаёт локальное виртуальное окружение `.venv` (существующая папка не удаляется).
4. Загружает архив закреплённого commit Windows-бандла (Git не нужен) и проверяет SHA-256 blob-ресурсов.
5. Запускает панель на `http://127.0.0.1:8787`.

`pip install` для обычного запуска не требуется: панель использует стандартную библиотеку Python. Установщик не меняет постоянную PowerShell Execution Policy, не включает автозапуск, не запускает `winws2` и не меняет firewall.

Если WinGet отсутствует, установите **App Installer** из Microsoft Store или Python 3.11+ вручную с [официальной страницы Python](https://www.python.org/downloads/windows/), затем запустите `setup.bat` ещё раз.

## Ручная установка и обслуживание

Остальные действия можно выполнить отдельно из PowerShell, если автоматический установщик не подходит:

```powershell
py -3 --version
py -3 -m venv .venv
```

Python должен быть версии 3.11 или новее. Виртуальное окружение изолирует Python проекта.

### Загрузить Windows-бандл и ресурсы

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_windows.ps1
```

Bootstrap:

1. Скачивает ZIP Windows-бандла `zapret-win-bundle` на закреплённом commit (новая установка не требует Git).
2. Проверяет наличие `winws2`, Lua-библиотек, WinDivert-фильтров и компонентов Blockcheck2.
3. Загружает недостающие blob-файлы в `runtime/blobs/` и сверяет их SHA-256.

Файлы размещаются только внутри папки проекта (`vendor/` и `runtime/`). Bootstrap не запускает `winws2`, не меняет firewall и не устанавливает службу автозапуска. При повторном запуске уже проверенные ресурсы не скачиваются заново.

### Если PowerShell блокирует сценарии

Не нужно менять политику выполнения навсегда. Запускайте нужный сценарий отдельным процессом:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_windows.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Параметр применяется к запущенному процессу PowerShell и его дочерним процессам; он не записывает новую постоянную политику. Если устройство управляется организационной групповой политикой, локальный обход может быть запрещён. [Документация Microsoft о политиках выполнения](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_execution_policies).

### Запустить панель

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Откройте **http://127.0.0.1:8787**. Оставьте окно PowerShell открытым: в нём работает локальный HTTP-сервер. `Ctrl+C` останавливает только сервер панели.

После первой установки можно запускать `start.bat` двойным щелчком.

Панель не запускает `winws2` сама. Команду можно проверить в интерфейсе, а старт и остановка выполняются отдельными кнопками с подтверждением.

## Использовать уже установленный `winws2.exe`

По умолчанию панель использует исполняемый файл из закреплённого `vendor/zapret-win-bundle`. Если нужно выбрать другой `winws2.exe`, задайте `ZAPRET2_DIR` — путь к папке, **в которой непосредственно находится `winws2.exe`**:

```powershell
$env:ZAPRET2_DIR = 'C:\Tools\zapret2\zapret-winws'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Это переопределяет только расположение исполняемого файла. Lua-библиотеки, фильтры и другие поддерживающие файлы панель по-прежнему ожидает в `vendor/zapret-win-bundle`. Не используйте `-SkipBundle` как замену bootstrap, если совместимый bundle ещё не находится в `vendor/`.

## Обновить проект и ресурсы

```powershell
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_windows.ps1
```

Для Git-клона используйте `git pull --ff-only`. Если вы установили приложение из ZIP, скачайте и распакуйте ZIP следующего релиза в новую папку; перенесите туда `runtime/`, чтобы сохранить стратегии и списки. Эта папка не входит в релизный архив. Если в `vendor/zapret-win-bundle` есть локальные изменения или другая версия, bootstrap остановится и не перезапишет её.

## Права администратора и автозапуск

Просмотр панели и настройка профилей рассчитаны на обычный запуск. Установка или удаление службы `zapret2-webcontrol` требует административных прав и доступна только из процесса панели, запущенного от имени администратора. Поскольку у локального API нет пароля, не выставляйте его за пределы `127.0.0.1` и закройте административно запущенную панель после операции.

## Удаление

1. Остановите `winws2` в панели.
2. Если служба автозапуска установлена, удалите её из панели с административными правами.
3. Сохраните `runtime/`, если нужны пользовательские стратегии и списки.
4. Закройте сервер `Ctrl+C` и удалите папку проекта.

Если удалить папку раньше службы, служба может остаться зарегистрированной, но потерять файлы, на которые она ссылается.

## Устранение неполадок

| Симптом | Что проверить |
| --- | --- |
| WinGet не найден | Установите App Installer из Microsoft Store или установите Python 3.11+ вручную с python.org, затем повторите `setup.bat` |
| `py` не найден после установки | Закройте окно и запустите `setup.bat` повторно; проверьте Python Launcher в списке установленных приложений |
| Установщик сообщает о повреждённом `.venv` | Переименуйте существующую `.venv` в резервную папку и повторите `setup.bat`; установщик сам ничего не удаляет |
| Ошибка проверки существующего бандла | Старый Git-бандл требует Git for Windows; новая установка из ZIP Git не требует |
| PowerShell сообщает `PSSecurityException` | Запустите скрипт через `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ...` |
| `winws2.exe` не найден | Успешно ли завершился bootstrap; для внешней установки проверьте `ZAPRET2_DIR` |
| Предпросмотр содержит предупреждения | Откройте подробности команды; проверьте доступность файлов списков и blob-ресурсов в `runtime/` и `vendor/` |
| Страница не открывается | Убедитесь, что окно с `run.ps1` всё ещё работает и адрес — `http://127.0.0.1:8787` |
| Не удаётся установить службу | Запустите панель от имени администратора только на время установки/удаления службы |
